## canary.22 做了什么（owner 第七轮 + 两处拍板落地）

### 1. 上下弹窗分界（owner：下面放不下为什么不向上弹）

**根因是量错了高度**：上一次定位钉下的 `max-height` 会把 `offsetHeight` **夹住**，
于是内容长高之后再量还是那个被夹住的旧值，判据以为「下面放得下」，永远不翻上去 ——
表现就是赖在下面并出滚动条。**量之前必须先松开自己上一次施加的约束**（`maxHeight = ""`）。

分界线同时改成三句话，按优先级：

1. **下面放得下就放下面**（阅读顺序自然，也是原生习惯）；
2. **下面放不下、上面放得下就翻上去** —— 这条是新补的。
   旧判据是「下面放不下**且** below < above 才翻」，于是「下面差一点点、但仍比上面宽」
   会赖在下面出滚动条，正是 owner 看到的；
3. 两边都放不下才比谁宽，挑宽的那边并钉住 `max-height`（这时出滚动条没办法，但绝不出界）。

题目卡与用户卡走的是**同一个** `placeCard`，所以「展开简介后越界」和「展开标签后越界」
是同一处判据，一并修好。两条反证测试都在，其中一条专门盯「夹住不松开就发现不了长高」。

### 2. 屏蔽的确认框 → 卡内就地确认（owner 拍板）

而鼠标一移开卡片自己就该收起来。`window.confirm` 已从整个块里移除（有反证守卫）。
★ 顺带把「问一句」的责任整个搬到视图层：`follow-action` 拿到调用就直接发，
所以**视图层必须先问**这条由 `test/hover-card-render.test.mjs` 守着 —— 那是安全判据，不是样式。

## canary.21 做了什么（owner 第六轮）

owner 报的两条其实是**同一层**（薄壳）的两个独立原因，都在这一轮拔掉了。

### 1. 「悬停用户名不弹，蹭一下头像才弹」——★★★ 薄壳看不见的元素，块永远没机会加载

私信页联系人行的用户名是个**裸 span**（整行只有头像带 uid），压根不匹配薄壳的候选选择器
→ 探针不响 → 块不加载 → 名字毫无反应；先蹭一下头像把块拉下来，之后名字才开始工作
（块里的 `/chat` 行兜底这时候才有机会跑）。

**判据从「指针压在候选上」换成「这一页有没有可预览的东西」**：
指针压在候选上 → 立刻拉；没压在上面 → 只要这一页存在正文候选（**站点框架里的不算**，
每页顶栏都有我自己的头像），指针一动照样拉。
★ 这不是把范围放宽一点，而是**把「按元素猜」这条会一直漏的路整个换掉** ——
块由**页面**决定加不加载，不再由「指针碰巧压在什么上」决定。
★ 按需加载的意义仍在：整页没有可预览内容、或只有框架里的候选，一个字节都不拉（都有反证测试）。

### 2. 「第一次悬停不弹」——补发的合成事件仍然要再等 300ms

canary.17 的修法是挂载后补发一次 `mouseover`。它能让块收到事件，但**那个事件照样要走
300ms 停留计时** —— 用户等块下载已经停了几百毫秒，再要求他重新停一次，体感还是不弹。

改成：薄壳把**指针坐标**交给块（`mount({ replayAt })`），块自己解析并调
`intent.open()` **立刻开卡**。顺带不再跨 realm 造合成事件（那条路本来就脆）。

### 3. 逐页扫查（owner 要求「所有涉及页面都仔细审核一遍」）

写了个机械判据在真机上逐页跑：**找出所有「像用户名」（等级色、非纯数字、不在
用户/题目链接里）的叶子文本元素，看它所在行有没有头像可以给出 uid**。

| 页面 | 结果 |
|---|---|
| `/chat` 私信 | **有洞** —— 用户名是裸 span（`div.item > span.avatar > img` + `div > span > span[名字]`） |
| `/record/list` 提交记录 | 干净 —— 用户名在 `a.color-none{/user/116524}` 里（我一开始按 DOM 树深度截断误判成有洞，往下多看一层才发现是链接） |
| `/article` 文章广场 | 干净（16 个 `.luogu-username`） |
| `/discuss` 讨论区 | 干净（58 个）；唯一命中的是被我们自己染色的题号 `P5684`，那一行没有头像 |
| `/problem/list` 题库 | 干净 |

**只有 `/chat` 一处**。但既然「按元素猜」这条路本身会一直漏，第 1 条的改法已经把这一类
从根上去掉了 —— 以后再出现同形状的页面，不需要再补名单。

## ★★ 判据与教训

### 永远红不了的门等于没有门 —— 这次是真的被咬了

`quality.mjs` 原先**只量正式版产物**（按 `LuoguSP.user.js` 的 `@version` 去
`cdn/releases/<version>/` 取 manifest），canary 完全不在测量范围内。后果本轮真实发生：
**hover 块超预算 76 B 被发了出去，而 `quality budgets passed` 照常打印**。
已修：新增 `canaryOptionalBundles`，把 `cdn/channels/canary.json` 指向的 manifest 里的可选块
也按同一套预算量一遍，**新增块没配预算会直接报 `has no budget entry`**（而不是静默跳过）。
配了结构守卫。★ 判据：**任何「只量某一条产线」的门，都要问一句「另一条产线谁在量」。**

### 组件原文 >>> 页面抽样；配置端点 >>> 组件原文

上一轮靠「41 个用户零反例」定的徽章规则，被组件原文推翻两处。
这一轮组件原文里的枚举又是 `inject` 进来的，追到底才发现 **`/_lfe/config` 才是源头**。
判据：**要「和原生一致」，顺序是「配置端点 → 组件原文 → 页面抽样」，越靠前越可信。**
取法：页面里 `performance.getEntriesByType("resource")` 找 chunk → curl → 读；
配置直接 `curl /_lfe/config`。

### 同名字段不同含义，是最难发现的那种错

两个用户接口都有 `submittedProblemCount`，一个 5441 一个 710。
**光看字段名会以为可以互换**，实际差 8 倍。判据：**换数据源时，逐字段拿两边的真实值对一遍，
并且和页面上显示的数字对齐**（洛谷个人页写的是 710，这才是决定性证据）。

### 「块加载完了」不等于「用户看得见」

按需块是被某个事件拉下来的，等它挂好监听时**那个事件已经过去了**。
用户如果停着不动就再也不会有新事件 —— 表现为「第一次悬停没反应，晃一下才出来」。
判据：**任何「懒加载 + 事件委托」的组合，都要在挂载后补发一次当前状态**，
而且要按**指针现在的位置**补，不是当初那个 target（下载期间指针会移动）。

### 只按新版 DOM 写判据，会漏掉一整类页面

`.top-bar / .lside / .rside` 覆盖了所有 columba 页，**首页是旧版页**，用户菜单叫
`nav.user-nav`。判据：**洛谷新旧两代页面至今混跑，DOM 判据要两代各扫一遍**。

### 「移到卡片上不算离开」的快路径会跳过清理

`onOut` 里 `relatedTarget` 落在卡上就 `return`，**跳过了 `leave()`**，而 `leave()`
正是负责 `cancelOpen()` 的地方。判据：**任何「早退」都要问：我跳过的那条路上原本还负责释放什么？**

### 密排锚点之间没有空隙

练习页题号是零垂直间距铺开的（实测 A.bottom=193、B.top=193）。
「把卡片放在锚点下方 N px」，指针去卡片路上**必然横穿别的锚点**。

### `Number(null) === 0` 且 `Number.isFinite(0)` 为真

已经咬过四次。必须显式排除 `null` / `undefined` / `""`。

### 类选择器的 `display` 会压过 UA 的 `[hidden]`

**任何给了 `display` 的元素都必须自己再声明一次 `[hidden]{display:none}`。**

### 结构守卫拦得住「声明了却没人接」，行为测试拦不住

按需块的接线漏一处功能就静默消失，而行为测试注入的是自己的 `loadBundle`。
★ 反证本身也要确认破坏真的落地了（本轮两次：`cancelOpen`、补发悬停，删掉都当场变红）。

### 页面 CSP 挡死页内 fetch 任何外部主机

想把已发布的块 import 进真页面做验证是走不通的（连我们自己的 CDN 都拉不到）。
**验证渲染用 jsdom 或本地样张**（`node -e` + esbuild 打个 demo 包 + `python -m http.server`）。

### 隐藏标签页里 rAF 不触发 / 搬进另一个 realm 等于换了一套宿主对象

实机审计必须让窗口与标签页处于前台；hover 卡因此改用事件委托。
跨 realm 的构造器要从 `document.defaultView` 取（补发 mouseover 就是这么写的）。

## 一手契约（全部实测）

### hover 卡的数据源

| 用途 | 请求 |
|---|---|
| 题目 | `GET /problem/{pid}` + `x-lentille-request: content-only` |
| 标签字典 | `GET /_lfe/tags`（32389 B，可长缓存，**里面没有难度**） |
| 上次尝试 | `GET /record/list?user={uid}&pid={pid}` ★ **旧版页面**，数据在 `_feInjection.currentData.records` |
| 用户（主） | `GET /api/user/info/{uid}` |
| 用户（补） | `GET /user/{uid}` + lentille header |
| 实时评论 | `GET /article/{lid}/replies` |

字段坑：`problem.tags` 是**数字 id**，要配 `/_lfe/tags`；`data.lastCodeAt` 是 IDE 最后保存时间
**不是**最后提交；`problem.accepted`/`.submitted` 是**按访问者算的布尔**；
`data.prizes[i]` **套了一层** `{prize:{year,contest,event,prize}}` 且**按年份升序**；
匿名 curl 取 `.cn` 会先吃一发 `302 + Ws-Action: cc`（CDN cookie 挑战），**带 cookie jar 重试就过**。

### `bestRecord` 按什么挑（owner 问过三次）

用 `U268427` 反证（4 次提交）：最新一次 95 分**没被选中**，`bestRecord` 是更早的 100 分
→ **分数优先，不是时间优先**。同分三条里选中的那条**同时是最新的也是最快的**，
所以「同分取新」还是「取快」**仍分不开，不编**。

### 官方互动写契约

```
POST /article/{lid}/favor[?remove=1]     响应体不参与状态
POST /article/{lid}/vote?vote={-1|0|1}   响应体 {upvotes, voted} 是权威
POST /api/user/updateRelationShip        ← 注意 Ship 的 S 大写
  Content-Type: application/json / X-CSRF-TOKEN / X-Requested-With: XMLHttpRequest
  {"uid": 116524, "relationship": 0|1|2}  → 200 {"_empty":true}
```

★ 响应体**都不回传新状态** → 必须乐观更新 + **失败回滚**，并把同一目标的写请求串行化。

### 受限文章的实时计数与真实发表时间

```
GET /user/{authorUid}/article?page={N}[&category={C}]   Header: x-lentille-request: content-only
```

文章**页面**路径被 WAF 拦，但**作者专栏列表 API 没拦**；`time` 是**真实发表时间**
（保存站的 `createdAt` 是入档时间，实测差三个月）；`content` 截断到 128 字；
列表**不含** `voted`/`favored`、**不按时间排序**、`perPage` 固定 10、`?category=N` 有效、`?keyword=` 无效。
页面 CSP 挡死页内直连 `api.luogu.me` → 保存站必须走 `GM_xmlhttpRequest`。

### 云剪贴板

洛谷**有** `/paste` 但**只列自己的**；他人剪贴板的真实发表时间在 .cn 上无来源，
所以那一行一律标注「**存档时间**」（owner 拍板）。
