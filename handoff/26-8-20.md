要退的是**自定义域 + DNS 记录 + worker.js 里的 legacy 分支**，不是 worker 本体。

**2. 真正的判据不是「2.14.0 之前」，而是「谁的 `@require` 还指着 spcdn」。**
把历史版本的 `@require` 主机与 `@updateURL` 全拉了一遍：

| 版本 | `@require` 主机 | `@updateURL` | 9/5 之后 |
|---|---|---|---|
| ≥ 2.13.7 | `luogusp.round1.cc` | cnb.cool | **不受影响** |
| 2.13.6 | **spcdn.betaoi.cc** | cnb.cool（活的，现供 2.14.3） | **会自己升走**，不受影响 |
| 2.13.4 / 2.13.5 | **spcdn.betaoi.cc** | gitee.com/shanire/LuoguSP | ⚠ **仅此一档会被断掉** |
| 2.13.0 – 2.13.2 | `spcdn.betaoi.**cn**` | gitee | 该域名**早已不解析**，这批人已经死了 |
| ≤ 2.12.5 | cdn.jsdelivr.net | gitee | 与本决定无关 |

## ★★ 判据与教训

### 状态类记录会腐烂，判据类不会

上一份交接单写着 2.14.1，实际已经到 2.14.3；memory 索引也照抄了那个数字。
**记「判据怎么取」能活，记「现在是什么状态」会死。** 开局先 `git log`。

### 永远红不了的门等于没有门 —— 已经被咬了两次

- `quality.mjs` 原先**只量正式版产物**，canary 完全不在测量范围内 ——
  **hover 块超预算 76 B 被发了出去，而 `quality budgets passed` 照常打印**。
- pnpm 迁移把 `pnpm release` 改成一开口就 `ReferenceError`，**`pnpm check` 三天全绿**
  （没有任何一条路径碰得到 `publish.mjs` 的顶层）。

★ 判据：**任何「只量某一条产线」的门，都要问一句「另一条产线谁在量」；
任何没有门跑过的脚本，都要假定下一次重构会把它改烂。**

### 夹具与真站形状不一致 ⇒ 门只看得见「挂上了」，看不见「挂错了」

2.14.3 的根因。★ 而**反证材料通常是现成的**：不可变旧版发布物还在 CDN 上，
拿上一版的真实字节当对照组，比手工构造坏样本可信得多。

### 判据不能依赖被守护操作的中途状态

发布预检门规划「当前版本 + 1」，而它跑在发布流程内部、目录已经建好之后 ——
**把它该保护的那次发布拦死了**。规划一个永远不可能存在的版本才对。

### 判据可信度排序：`GET /_lfe/config` > 组件原文 > 页面抽样

靠「41 个用户零反例」定的徽章规则被组件原文推翻两处；组件原文里的枚举又是 `inject` 进来的，
追到底 **`/_lfe/config` 才是源头**。取法：页面里 `performance.getEntriesByType("resource")`
找 chunk → curl → 读；配置直接 `curl /_lfe/config`。

### 「A 处没有」推不出「B 处没有」——先看清那条结论当初是对着哪个来源说的

交接单记的「他人剪贴板的真实发表时间在 .cn 上无来源」说的是 **.cn 站**，
而保存站抓的是 `www.luogu.com` —— 上游类型里 `Paste` 同样声明 `time: number`。
**两侧完全同形，差点因为一条张冠李戴的旧结论少修一半。**

### 同名字段不同含义，是最难发现的那种错

两个用户接口都有 `submittedProblemCount`，一个 5441 一个 710（差 8 倍）。
判据：**换数据源时逐字段拿两边真实值对一遍，并和页面上显示的数字对齐。**

### 「块加载完了」不等于「用户看得见」

按需块是被某个事件拉下来的，等它挂好监听时**那个事件已经过去了**。
判据：**任何「懒加载 + 事件委托」的组合，都要在挂载后按指针的\*现在\*位置补发一次**，
不是当初那个 target（下载期间指针会移动）。

### 「按元素猜」这条路会一直漏 —— 要换掉，不是放宽

私信页用户名是裸 span，薄壳的候选选择器认不出 → 块永远不加载。
修法不是补选择器名单，而是**把判据从「指针压在候选上」换成「这一页有没有可预览的东西」**，
块由**页面**决定加不加载。以后出现同形状页面不需要再补名单。

### 只按新版 DOM 写判据，会漏掉一整类页面

**洛谷新旧两代页面至今混跑**（首页是旧版页，用户菜单叫 `nav.user-nav`）。DOM 判据要两代各扫一遍。

### 其它已被咬过的小判据

- 「移到卡片上不算离开」的**快路径会跳过清理** —— 任何「早退」都要问：我跳过的那条路上原本还负责释放什么？
- **量高度之前必须先松开自己上一次施加的约束**（`maxHeight = ""`），否则量到的是被夹住的旧值。
- 密排锚点之间**没有空隙**（练习页题号 A.bottom = B.top = 193），「放在锚点下方 N px」必然横穿别的锚点。
- `Number(null) === 0` 且 `Number.isFinite(0)` 为真 —— 已经咬过四次，必须显式排除 `null`/`undefined`/`""`。
- 类选择器的 `display` 会压过 UA 的 `[hidden]` —— **任何给了 `display` 的元素都要自己再声明一次 `[hidden]{display:none}`**。
- 结构守卫拦得住「声明了却没人接」，**行为测试拦不住**（它注入的是自己的 `loadBundle`）。
  ★ 反证本身也要确认破坏真的落地了。
- **钉字段名不够，要钉整条表达式** —— `source.includes("assumeMinHeight")` 是假门，
  改回 `assumeMinHeight: 0`（也就是退回坏写法）它照样绿。
- 页面 CSP 挡死页内 fetch **任何**外部主机（连我们自己的 CDN 都拉不到）。
  验证渲染用 jsdom 或本地样张。
- 隐藏标签页里 rAF 不触发；跨 realm 的构造器要从 `document.defaultView` 取。
- **浮点**：`abbreviateCount` 内部走整数运算（先乘 100 再除），先除再乘会踩浮点 ——
  最小发散值实测是 **1130**（`1130/1000*100 === 112.99999999999999`）。

### 工具坑（跨项目复发）

- **`git checkout -- <file>` 撤的是到 HEAD，不是到我的工作态。** 用它撤「反证用的临时改动」
  会把同一文件上已经做完的重写一起抹掉。★ 另一半：**还没进版本库**的新文件，
  `git checkout` 直接报 pathspec 不存在 —— 反证留下的改动**根本没被撤回**。
  **反证要用 `cp` 备份还原，别用 git。**
- **heredoc 吃掉一层反斜杠**，且**不报错**，只把正则悄悄改写成永不匹配。
  **写脚本一律用 Write 工具落文件。**

## 一手契约（全部实测）

### hover 卡的数据源

| 用途 | 请求 |
|---|---|
| 题目 | `GET /problem/{pid}` + `x-lentille-request: content-only` |
| 标签字典 | `GET /_lfe/tags`（32389 B，可长缓存，**里面没有难度**） |
| 上次尝试 | `GET /record/list?user={uid}&pid={pid}` ★ **旧版页面**，数据在 `_feInjection.currentData.records` |
| 用户（主） | `GET /api/user/info/{uid}` |
| 用户（补） | `GET /user/{uid}` + lentille header |
| 实时评论 | `GET /article/{lid}/replies` |

字段坑：`problem.tags` 是**数字 id**，要配 `/_lfe/tags`；`data.lastCodeAt` 是 IDE 最后保存时间
**不是**最后提交；`problem.accepted`/`.submitted` 是**按访问者算的布尔**；
`data.prizes[i]` **套了一层** `{prize:{year,contest,event,prize}}` 且**按年份升序**；
匿名 curl 取 `.cn` 会先吃一发 `302 + Ws-Action: cc`（CDN cookie 挑战），**带 cookie jar 重试就过**。

### 用户数据的两个来源

| 来源 | 体积 | 有什么 |
|---|---|---|
| **主** `GET /api/user/info/{uid}` | 951–1647 B | 原生悬停卡自己调的那个。name/color/avatar/**background**/badge/slogan/ccf/xcpc/ranking/关注粉丝/registerTime/**userRelationship + reverseUserRelationship**（登录态才有）/**elo + eloValue 真值**/blogAddress |
| **补** `GET /user/{uid}` + lentille header | 12–20 KB | 只为拿 **`gu`（咕值）**、**`prizes`（获奖）**、以及**个人页口径**的 `submittedProblemCount` |

- ★★★ 两个接口的 `submittedProblemCount` **含义不同**：实测 697932，主接口 **5441**、
  补载荷 **710**，**洛谷个人页上写的是 710**。「通过 / 提交」这一行**只认补载荷**，拿不到就不画。
- ★★ **未通过实名认证的用户**：`/user/{uid}` 返回 **403**，而主接口 **200 全量** ——
  这类用户照样出卡，只是少了咕值 / 获奖 / 通过·提交三行。
- ★ 主接口的 `prize` 字段**不是获奖列表**（397982 有 8 个奖，那里仍是 `[]`）。获奖只能走补载荷。
- ★ 「`elo`/`eloValue` 恒为 null」**只对 `/user/{uid}` 成立**；主接口里两个都是真值。
- ★ 匿名（未登录）时主接口**不返回**两个 relationship 字段 → 关系只能是「未知」。

### 官方互动写契约

```

```

★ 响应体**都不回传新状态** → 必须乐观更新 + **失败回滚**，并把同一目标的写请求串行化。

### 受限文章

```
GET /user/{authorUid}/article?page={N}[&category={C}]   Header: x-lentille-request: content-only
```

文章**页面**路径被 WAF 拦，但**作者专栏列表 API 没拦**；`time` 是**真实发表时间**
（保存站的 `createdAt` 是入档时间，实测差三个月）；`content` 截断到 128 字；
列表**不含** `voted`/`favored`、**不按时间排序**、`perPage` 固定 10、`?category=N` 有效、`?keyword=` 无效。
页面 CSP 挡死页内直连 `api.luogu.me` → 保存站必须走 `GM_xmlhttpRequest`。

### 云剪贴板

洛谷**有** `/paste` 但**只列自己的**；他人剪贴板的真实发表时间在 .cn 上无来源，
所以那一行一律标注「**存档时间**」（owner 拍板）。

### `bestRecord` 按什么挑（owner 问过三次）

`U268427` 反证（4 次提交）：最新一次 95 分**没被选中**，`bestRecord` 是更早的 100 分
→ **分数优先，不是时间优先**。同分三条里选中的那条同时是最新也是最快的，
所以「同分取新」还是「取快」**仍分不开，不编**。

### 洛谷原生用户悬停卡（`UserFloatCard`）

- 组件 scopeId `data-v-77465168`，根节点 `.float-card`；外层是通用 dropdown。
  全站 chunk 里 `float-card` **只此一处**。
- `UserName` 的称号规则：`Cheater` → 「作弊者」；否则 `user.badge`；否则 `isAdmin` → 「管理员」。
- 「更多」菜单里**拉黑**走 `POST /api/user/updateRelationShip {relationship:2}`，
  **Following 状态直接拒绝**并提示「你无法拉黑正在关注的人」；**举报是纯链接** `/ticket/new?type=report.user&related={uid}`。
- ★★ **「全站启用原生卡」做不到 —— 没有开关可开**。`UserName` 组件默认就带这张卡，
  `no-card` 是逐调用点关掉的（全站只有 4 处）；所谓「只在少数地方有」其实是
  **只有少数页面用了这个组件**（`/article/jfc5mbj2` 21/21 全覆盖，首页 0/71）。
  所以我们只能自己画一张同款的补上。
- 屏蔽原生卡的方式：**用户卡开关打开时注入一条 CSS 藏掉 `.float-card`**，关掉就还回去。
  ★ 没去掐事件 —— 原生触发器的监听挂在触发元素上，要拦就得在 document 捕获阶段
  `stopPropagation`，那会连带掐掉那棵子树上别人的一切 mouseover，代价不可控。
  代价是原生那边照样会发一次 `/api/user/info/{uid}`（约 1 KB），可以接受。

## 架构：三个按需加载块

启动包只留**廉价探测器**，重机械按需拉（机制在 `src/cdn/optional-bundle-loader.js`）。

| 块 | 入口 | 触发条件 | 薄壳 |
|---|---|---|---|
| `markdownRenderer` | — | 需要渲染 markdown 时 | `hidden-intro/renderer-client.js` |
| `restrictedContent` | `src/cdn/restricted-content-bundle.js` | 探测到「安全访问中心」拦截页 | `restricted-content/lazy-feature.js` |
| `hoverCard` | `src/cdn/hover-card-bundle.js` | 这一页存在正文候选（**站点框架里的不算**） | `hover-card/lazy-feature.js` |

★ hover 卡有**两个开关**（`showProblemHoverCards` / `showUserHoverCards`）但**共用同一个块、
同一次挂载**（引用计数：第一个打开时装壳，最后一个关掉才拆）；块通过薄壳注入的
`isEnabled(kind)` **现问**，所以设置里改开关立刻生效、不必重挂。

加一个新块要动：`scripts/cdn/build.mjs`、`config/quality-budget.json`、`scripts/quality.mjs`
（**含 canary 预算映射表**）、`scripts/cdn/verify-production.mjs`、`scripts/publish-lib.mjs`，
再加一组结构守卫。★ 校验一律是「清单声明了就必须钉全」而不是「必须存在」。

### 行为哈希（`scripts/artifact-behaviour-hash.mjs`）

`reports/browser-qa.json` 用产物 sha256 证明「这份产物真的在浏览器里跑过」，
但改一行 `@description` 就让一份如假包换的 QA 整份作废。所以另算一个行为哈希：
**只把 `@description` 那一行抹成占位符**，`@require`/`@match`/`@grant`/`@connect`/
`@run-at`/`@sandbox` 与脚本体**一个都不豁免**。老报告没有该字段时，门自动退回整份严格比对。
反证在 `test/artifact-behaviour-hash.test.mjs`（八处逐个验过）。

### 合同测试的两组标签（别混）

- `SOURCE_LABELS` —— `@description` / README 必须与**当前源码**一致（防漂移）；
- `SHIPPED_LABELS` —— **已经发出去的那一版** runtime 里确实含有的标签，
  只有这部分能对正式版 runtime 做包含断言。

### 上游的规矩（下次再给 luogu-saver 提 PR 直接照这个来）

- `AGENTS.md` 是**硬性** spec-first：改后端前必须先读 `spec/*.spec.md`，
  **spec 与代码必须在同一 PR 内对齐**，写成 low-entropy、可测的英文。

  从 `created_at` 推或填 0 都是**把未知伪造成已知**。
