# LuoguSP 2026-08-12 Canary 验收交接

## 结论

`2.14.0-canary.4` 已部署到 CDN，实时评论功能已由用户验收可用；收藏与点赞仍有状态一致性缺陷，当前 Canary **不能转为正式版**。晚上继续处理时，应先修复下述问题，再重新构建新的 Canary 版本并完整回归。

## 用户验收发现：收藏与点赞状态不一致

### 现象

1. 页面初次打开时，点赞数和收藏数来自保存站的存档快照，并非洛谷实时值。
2. 用户主动点赞或收藏后，洛谷官方写接口会返回真实数据，界面会瞬间从保存站快照跳到真实数据；两者差异可能很大，视觉刷新明显。
3. 随后的组件刷新或页面刷新又会重新使用保存站的 `upvote` / `favorCount`，真实计数被覆盖回旧快照。
4. 页面刷新后，当前账号的 `favored` / `voted` 状态也会丢失，按钮不再显示已收藏或已点赞。
5. 因前端误以为当前账号没有收藏或点赞，用户无法可靠地发起“取消收藏”或“撤回点赞”。

### 当前代码路径

- `src/features/restricted-content/feature.js`：构造文章上下文时直接以保存站的 `data.upvote` 和 `data.favorCount` 填充 `article`；每次重新引导页面都会恢复这份快照。
- `src/features/restricted-content/article-interaction-state.js`：只接受保存站数据中的布尔 `favored` 和 `-1/1` 的 `voted`；保存站实际不提供当前登录账号的这两个字段，因此刷新后通常回到 `null`。
- `src/features/restricted-content/article-write-adapter.js`：目前只保证官方写请求保持同源 Cookie 和 CSRF，不负责保存、合并或恢复写成功后的真实互动状态。
- `test/saver-and-restricted.test.mjs`：已覆盖字段形状和官方请求传输安全，但尚未覆盖“保存站旧快照 → 官方写响应 → 页面/组件刷新 → 仍能取消”的完整状态生命周期。

### 初步判断

这是“公共存档快照”和“账号实时状态”被当作同一数据源造成的。保存站 API 只能作为初始公共计数的降级数据源，不能作为个人 `favored` / `voted` 状态的权威来源；官方写成功后也不能再次用保存站快照覆盖已确认的服务器结果。

受限文章页面目前没有已确认可用的只读接口来恢复当前账号的收藏/点赞状态。因此修复时需要先验证是否存在同源、带当前 Cookie 的官方只读状态来源；若确实不存在，再设计按“账号 UID + 文章 ID”隔离的本地持久状态，并明确其与官方写响应、保存站公共快照之间的优先级和失效策略。不能把未知状态伪造成 `false`。

## 晚上继续时的修复目标

1. 建立单一互动状态模型，至少同时管理：
   - 公共计数：`upvote`、`favorCount`；
   - 当前账号状态：`voted`、`favored`；
   - 数据来源和新鲜度：保存站快照、官方写响应、可用的官方只读响应、本地持久状态。
2. 初次显示可以使用保存站公共快照，但应避免在官方真实值返回时产生突兀跳变；至少需要在 UI 上保持状态更新原子化，不能一部分先变、一部分后变。
3. 官方点赞、取消点赞、收藏、取消收藏成功后，以服务器响应为准更新计数和个人状态，并按账号与文章隔离保存已确认状态。
4. 组件重新渲染或页面刷新时，不得用旧保存站快照覆盖更新、更可信的状态。
5. 写入失败时恢复点击前状态；不得持久化乐观更新。
6. 必须支持刷新后撤回此前点赞或收藏。
7. 账号切换、退出登录、文章切换时不能串用个人状态；本地记录应包含账号身份并设计过期/清理规则。
8. 保存站数据后续更新时，只在其比当前公共快照更新且不会覆盖已确认个人状态时合并。

## 建议新增的回归测试

1. 保存站初始计数较旧，官方点赞成功返回较新计数：界面和内部状态以官方响应为准。
2. 官方收藏成功后触发组件重新挂载：不得恢复为保存站计数或未知个人状态。
3. 模拟完整页面刷新并恢复同一账号、同一文章：仍显示已收藏/已点赞，下一次点击调用官方取消接口。
4. 点赞、收藏写入失败：计数、按钮状态和持久记录全部恢复。
5. A 账号的状态不能被 B 账号读取；匿名状态不能继承登录账号状态。
6. 保存站刷新返回旧值：不得覆盖更可信的官方确认状态。
7. 取消点赞使用官方 `vote=0`，取消收藏使用官方 `favor?remove=1`，并验证 Cookie、CSRF 及用户主动点击约束不变。
8. 评论实时优先、保存站回退及剪贴板只读行为继续通过，防止修复互动状态时产生回归。
