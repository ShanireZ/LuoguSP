## ★★ 判据与教训（每条都在本轮真实付出过代价）

### 验证环境不能天然满足真实环境不满足的前提

- 用本机 `curl` 判定「国际站匿名可读」→ **本机挂着 TUN 代理**，整套方案作废。
- 更早一次：Playwright 的 `addInitScript` 注入的是**主世界**，天然满足了用户脚本沙箱
  不满足的前提，测试全绿而毫无价值。

判据：**任何「可达性 / 环境」结论都必须在真实用户环境下复验。**

### 搬进另一个 realm，等于换了一套宿主对象

`{ setTimeout, clearTimeout }` 简写会让 `clock.setTimeout(...)` 以 `this === clock`
调用原生方法。用户脚本沙箱里 `setTimeout` 是 Tampermonkey 的包装函数、不挑 `this`，
**侥幸跑了两个 canary**；一旦模块随按需块经 `blob:` 动态 `import` 在**页面 realm** 执行，
立刻 `TypeError: Illegal invocation`。仓库里的正确写法是包一层：
`setTimeout: (fn, ms) => setTimeout(fn, ms)`。已有结构守卫扫全仓。

### 接手早退逻辑时，先问它原来还负责释放什么

早期加载层在 `document-start` 就用 `body>*{visibility:hidden}` 遮住**所有**
`/article/*`、`/paste/*`（不只是拦截页），原本由 `document-boot` 在探测失败时释放。
薄壳提前 `return` 却没释放 → **每个正常文章/剪贴板页面被永久遮成空白**。

### 结构守卫拦得住「声明了却没人接」，行为测试拦不住

按需块的接线只要漏一处（应用根引错文件、runtime 没接加载器、build 没写清单），
功能就静默消失，而所有行为测试仍然全绿 —— 它们注入的是自己的 `loadBundle`。
所以每个按需块都配了结构守卫。

### ★ 守卫自己也会「永远红不了」

给铁律写的守卫第一次是**假绿**：剥注释用了 `/\/\/[^\n]*/`，它把 `https://` 里的 `//`
当成注释起点、**连带删掉整行**，而守卫要找的 URL 正好在那一行。
**剥注释必须限定行首**（`/^[ \t]*\/\/[^\n]*$/gm`）。
同理，讲坑的注释里天然含反例字面量，正则会误报到自己身上 ——
要么剥注释，要么收紧到真正的代码位置（`[=:]\s*\{…\}`）。

**并且：反证本身也要确认破坏真的落地了。** 有一次 `sed` 的多行删除没生效、测试照绿，
换 python 重做才真的红。

### `Number(null) === 0` 且 `Number.isFinite(0)` 为真

本轮**咬了三次**（canary.7 的计数、`abbreviateCount`、`statusPresentation`）。
只判 `isFinite` 会把「字段缺失」悄悄变成 0/Unaccepted。必须显式排除
`null` / `undefined` / `""`。

### 类选择器的 `display` 会压过 UA 的 `[hidden]`

`.luogusp-hc-taglist{display:flex}` 让 `hidden` 属性完全失效，表现为
「标签默认就展开、切换按钮看着失效」。**任何给了 `display` 的元素都必须自己再声明一次
`[hidden]{display:none}`。**

### 修复也会过度

把 pid 判据全交给 `problem-color/identity.js` 后，题库列表里的题目**反而不弹卡**了 ——
它额外要求「锚点文本真的显示该 pid」，那是为**着色**设计的判据，而题库行的链接文本是**题名**。
判据：**复用别处的校验前，先确认它的语义和你的场景一致。**

### 隐藏标签页里 rAF 不触发

扩展驱动的标签页 `visibilityState === "hidden"`，`requestAnimationFrame` 不触发。
`settings` / `hidden-intro` / `ide-batch` / `restricted-content` 都用 rAF 节流
MutationObserver，`page-lifecycle.remount()` 也是「先卸载再 schedule(rAF) 挂载」——
隐藏标签页里 SPA 路由切换后功能会暂时全部卸载，**看着像坏了，一可见就自愈**。
实机审计必须让窗口与标签页处于前台。hover 卡因此改用**事件委托**，不碰 rAF。

## 一手契约（全部实测，是施工依据）

> 全部在 owner 的 Edge、真实登录态（uid 1313427）下取得。除「操作留痕」列出的一次授权
> 写入外，全部是 GET。

### 受限文章的实时公共计数与真实发表时间

```
GET /user/{authorUid}/article?page={N}[&category={C}]
Header: x-lentille-request: content-only
→ data.articles = { perPage: 10, count, result: [ … ] }
→ result[i] = { lid, title, category, time, author, upvote, replyCount,
                favorCount, status, solutionFor, promoteStatus, collection, content }
```

- 文章**页面**路径被 WAF 拦（`/article/{lid}` 加 header 或 `?_contentOnly=1` 都返回
  2528B 的「安全访问中心」），但**作者专栏列表 API 没拦**。
- `2l4x53kj` 实测 `upvote: 24`，与 owner 真机点赞测出的真值一致；保存站快照当时是 19。
- `time` 是**真实发表时间**。保存站的 `createdAt` 是**入档时间**，两者实测差三个月
  （入档 2026-01-02，真实发表 2025-10-01）。
- `content` 截断到 128 字 → 正文仍靠保存站。
- 列表**不含** `voted` / `favored` → 个人状态只能来自官方写响应 + 本地持久层。
- **不按时间排序**（跨页乱序，实测），所以不能二分只能扫；`perPage` 固定 10，
  `?perPage=50` 无效；`?category=N` **有效**（26 篇 → 4 篇），`?keyword=` **无效**。
- 页面 CSP（`<meta>`，非响应头）挡死页面内直连 `api.luogu.me` → 保存站必须走
  `GM_xmlhttpRequest`。**拦截页本身没有 CSP meta**（2528B 裸页）。

### 官方互动写契约

```
POST /article/{lid}/favor[?remove=1]     响应体不参与状态，组件自行 favored=!favored、favorCount±1
POST /article/{lid}/vote?vote={-1|0|1}   响应体 {upvotes, voted} 是权威；撤回发 vote=0
POST /api/user/updateRelationShip        ← 注意 Ship 的 S 大写；同源，无 query
  Content-Type: application/json / X-CSRF-TOKEN: <meta[name=csrf-token]> / X-Requested-With: XMLHttpRequest
  {"uid": 116524, "relationship": 1}     ← 1 = 关注，0 = 取消
  → 200 {"_empty":true}
```

★ `favor` 与 `updateRelationShip` 的**响应体都不回传新状态** → 必须乐观更新 + **失败回滚**，
并把同一目标的写请求串行化（连点两次会让状态随机落地）。
★ 官方前端用 axios，`adapter: ["xhr","http","fetch"]` → 写请求实际走 **XMLHttpRequest**，
观察写响应必须挂在 XHR 层。
★ 关系枚举：`0` = 未关注、`1` = 已关注（`reverseUserRelationship: 1` 证实「他关注了我」）。
洛谷**没有**独立的枚举字典端点（`/_lfe/relationships`、`/_lfe/dicts`、`/_lfe/enums` 全 404）。
0/1 之外一律当未知，**不显示可点的关注按钮**。
